## 5. Boucle fonctionnelle canonique Product Completion

La boucle suivante est le **graphe nominal de référence** end-to-end (A→W). Ce graphe **≠** pipeline obligatoire séquentiel : **A** et **B** sont des **points d'entrée alternatifs** ; **Q**, **R**, **S** sont des **branches terminales** d'Attempt ; **W** est **transversal** (reprise inter-session à tout moment pertinent).

Chaque parcours significatif exige préconditions, acteur, scénario, variantes, erreurs, stop, gate, état final et Evidence.

### 5.0 Ordre majeur autorisation → exécution

```text
Préparer EC (K)
  → Inspecter EC (L) — Pilote
  → Confirmation si requise (M) — après inspection · pas avant préparation complète
  → Vérifier effective authority / executor sufficiency (N)
  → Exécuter (O→P)
```

**INTERDIT** : Confirmation systématique **avant** préparation EC · lancement Attempt sans EC complet **et** inspecté.

### 5.1 Vue d'ensemble A→W (graphe nominal)

```text
A  Créer Project                    ─┐
B  Retrouver / reprendre Project     ─┤ points d'entrée alternatifs
                                      │
C  Exprimer intention
D  Résoudre contexte / DoctrinePackage / sources
E  Qualifier cycle · profil · CKC · lenses
F  Clarification Nora
G  Mettre à jour LPS (Nora propose · Studio persiste)
H  Consulter / proposer ProjectTrajectory
I  Options / Recommendation
J  HumanDecision (Pilote) — si impact structurant
K  Préparer ExecutionContract
L  Inspecter ExecutionContract (Pilote)
M  Confirmation — si frontière protégée · après EC inspecté
N  Vérifier effective authority / executor sufficiency
O  Lancer Cursor/agent sous contrat
P  Suivre Attempt: accepted → running → terminal
Q  SUCCESS          ─┐
R  STOP gouverné     ─┤ branches terminales Attempt
S  FAIL technique    ─┘
T  Evidence / ReviewBundle (après TOUT terminal Q/R/S)
U  Analyse Nora
V  Replanification
W  Reprise inter-session (transversal)
```

### 5.2 Parcours A — Créer un Project

| Champ | Contenu |
| --- | --- |
| **Préconditions** | Session Studio **active / utilisable** |
| **Acteur primaire** | Pilote |
| **Scénario nominal** | 1) Pilote initie création 2) Fournit identité minimale (nom, objectif initial optionnel) 3) Studio crée Project + LPS initial + pin DoctrinePackage applicable 4) État Project = `active` (taxonomie fonctionnelle candidate) |
| **Variantes** | Création depuis template de contexte · import métadonnées harvest |
| **Erreurs** | DoctrinePackage indisponible / stale → **STOP** SC-SRC |
| **Gate** | **Aucun** gate Morris produit générique sur Create Project |
| **État final** | Project durable · LPS `initialized` · aucun Cycle actif obligatoire |
| **Evidence** | Audit event création · identité Project |

### 5.4 Parcours C→G — Intention · contexte · qualification · clarification · LPS

| Champ | Contenu |
| --- | --- |
| **Préconditions** | Project actif |
| **Acteurs** | Pilote · Nora · Studio |

| **Evidence** | Qualification trace · CKC path/version/status · sources list |

| --- | --- |

| **État final** | Trajectory `proposed` (Recommendation) ou `decided` (HD) · DecisionBasis lié · Studio matérialise |

### 5.6 Parcours K→N — EC · inspection · Confirmation · authority

| Champ | Contenu |
| --- | --- |
| **Préconditions** | Intention d'exécution identifiée · HD consommée **si** structurante requise · qualification → préparation contrat **sans** nouvelle HD si pas d'arbitrage structurant |
| **Scénario nominal** | K) Nora/Studio prépare EC natif **complet** → L) Pilote inspecte EC → M) Confirmation **si** protected boundary (§10) · **après** inspection → N) calcul effective authority · executor sufficiency |
| **Erreurs** | EC incomplet → STOP · executor insuffisant → SC-CAP · autorité insuffisante → `authority_blocked` (§7) |
| **Gate** | Confirmation N1/N2/N3 selon **effets / réversibilité / autorité / protections / policy** — **≠** profil seul |
| **État final** | EC `prepared` → `inspected` → `authorized` ou STOP / authority_blocked |
| **Evidence** | EC snapshot · Confirmation record si consommée |

### 5.7 Parcours O→P — Exécution

| Champ | Contenu |
| --- | --- |
| **Préconditions** | EC **complet** · EC **inspecté** · Confirmation requise **consommée / valide** · gates externes satisfaits · effective authority suffisante · executor sufficiency OK · HEAD/repo cohérent si applicable |
| **Scénario nominal** | O) Lancement agent → P) Attempt `accepted` → `running` → terminal (`terminal_success` \| `terminal_stop` \| `terminal_fail`) |
| **Variantes** | Read-only vs write local · docs-only vs code |
| **Erreurs** | Commande hors scope · protected path · timeout |
| **Stop** | Manuel · SC-PROT · SC-GIT · divergence |
| **État final** | Attempt terminal · CycleInstance **continue** (§7) |
| **Evidence** | Journal attempt · artefacts · **Evidence obligatoire avant claim terminal** |

### 5.8 Parcours Q/R/S — SUCCESS · STOP · FAIL

Voir §14. Evidence **requise pour chaque** terminal avant claim.

### 5.9 Parcours T→V — Evidence · analyse · replanification

| Champ | Contenu |
| --- | --- |
| **Préconditions** | Attempt terminal (Q/R/S) · Evidence produit ou en cours |
| **Scénario nominal** | T) Evidence/ReviewBundle produit → U) Nora analyse (business-first) → G/H) LPS + trajectory update (Nora propose · Studio persiste) → I) Recommendation next action → J) HumanDecision si structurante |
| **Gate** | Replanification structurante → HumanDecision |
| **État final** | CycleInstance en `replanning` ou retour qualification · **≠** fermeture automatique Cycle · **≠** archivage Project |
| **Evidence** | ReviewBundle · liens LPS |

### 5.10 Parcours W — Reprise inter-session (transversal)

Voir §15. Applicable à tout moment · pas une étape finale exclusive.

### 5.11 Règles transversales boucle

- Autorisation consommée **jamais extrapolée** au-delà de son scope / contexte / validité
- Re-Confirmation requise si scope · contexte ou validité changent **matériellement**
- Type cycle · CKC · profil **ne créent aucune autorité** · ne déterminent **pas seuls** N1/N2/N3
- Evidence après **tout** terminal SUCCESS / STOP / FAIL

## 7. États et transitions

**Anti-claim** : lifecycle fonctionnel **≠** architecture state-machine technique · **≠** implémentation d'états.

### 7.1 Principes

- **Séparer** lifecycle **CycleInstance** et lifecycle **ExecutionAttempt**
- **Ne pas** reprendre mécaniquement les 12 états historiques (`08`) ni le persona Morris acteur F1–F12
- Modèle **adapté** Pilote · Project≠Cycle · EC natif · recovery honnête
- `accepted` / `running` / `terminal_*` appartiennent à **ExecutionAttempt uniquement**
- Attempt terminal **ne ferme pas** automatiquement CycleInstance

### 7.2 États CycleInstance (fonctionnels)

| État | Signification |
| --- | --- |
| `intent_captured` | Intention enregistrée |
| `context_resolving` | DoctrinePackage / sources en cours |
| `qualifying` | Cycle/profil/CKC/lenses |
| `clarifying` | Questions Nora actives |
| `awaiting_human_decision` | Recommendation prête · HD requise (structurant) |
| `contract_preparing` | EC en préparation — **sans** HD supplémentaire si qualification suffisante |
| `contract_inspection` | EC présenté au Pilote |
| `awaiting_confirmation` | Frontière protégée · Confirmation pending |
| `authority_blocked` | Autorité/executor insuffisant · SC-CAP ou équivalent |
| `replanning` | Post-terminale Attempt · analyse / trajectory update |
| `cycle_paused` | Pause fonctionnelle (taxonomie candidate) |
| `cycle_closed` | Clôture cycle explicite — **≠** Project archived |

**Note** : `execution_accepted` / `execution_running` / `terminal_*` = états **ExecutionAttempt** (§7.3) — **pas** CycleInstance.

### 7.3 États ExecutionAttempt (fonctionnels)

| État | Signification |
| --- | --- |
| `accepted` | Attempt accepté · pas encore running |
| `running` | Exécution en cours |
| `terminal_success` | SUCCESS §14 |
| `terminal_stop` | STOP gouverné §14 |
| `terminal_fail` | FAIL technique §14 |

### 7.4 Transitions autorisées (extrait)

```text
CycleInstance:
intent_captured → context_resolving → qualifying → clarifying*
clarifying* → qualifying | awaiting_human_decision | contract_preparing
qualifying → contract_preparing (qualification suffisante · aucun arbitrage structurant · aucune HD nouvelle requise)
awaiting_human_decision → contract_preparing | requalification | replanning | cycle_paused | cycle_closed (explicite) | autre état fonctionnel défini — selon contenu HD consommée
contract_preparing → contract_inspection → awaiting_confirmation* → [Attempt launch via O]
authority_blocked → réduction scope | amendement EC | autre executor | requalification | nouvelle Confirmation | HD si structurant | STOP
[Attempt terminal] → replanning → qualifying | cycle_paused | cycle_closed (explicite)
replanning → qualifying | awaiting_human_decision

ExecutionAttempt:
accepted → running → terminal_success | terminal_stop | terminal_fail
```

**Note lifecycle** : une HumanDecision **≠** transition unique vers `contract_preparing` · les issues fonctionnelles dépendent du contenu de la décision (scope · trajectory · go/no-go · autorisation exécution · etc.).

`*` = optionnel selon gate · Confirmation **après** inspection EC

### 7.5 Transitions interdites

- `contract_inspection → running` sans inspection explicite Pilote
- `qualifying → running` sans EC complet + inspection + authority
- `terminal_fail → terminal_success` sans nouvel Attempt
- Toute transition créant HumanDecision ou Confirmation consommée **implicitement**
- Promotion Recommendation → HumanDecision automatique
- Attempt terminal → CycleInstance closed **automatique**
- Attempt terminal → Project archived **automatique**

### 7.6 Gates sur transitions vers Attempt

| Prérequis | Obligatoire |
| --- | --- |
| EC complet | Oui |
| EC inspecté par Pilote | Oui |
| Confirmation requise consommée / valide | Si applicable |
| Gates externes (ex. Morris construction repo SFIA Studio) | Si applicable |
| Effective authority suffisante | Oui |
| Executor sufficiency | Oui |

### 7.7 Après Attempt terminal

```text
Evidence (T) → Nora analyse (U) → LPS / Trajectory / Recommendation → CycleInstance continue
```

CycleInstance **≠** archivé comme seul outcome · clôture Cycle **≠** Project archived.
